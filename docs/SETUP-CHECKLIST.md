# Setup acceptance checklist

Keep the completed checklist and real links private. Mark each item Verified / Blocked / Not tested with evidence; do not check it merely because a schema exists.

## Account and resource identity

- [ ] Intended Google and Airtable accounts confirmed; human completed required consent/login.
- [ ] Correct workspace verified; base exists with real returned ID.
- [ ] Private Drive root/destinations created or reused; parents/sharing preserved.
- [ ] Goals and designated editable master located; content/version access tested.
- [ ] Missing inputs explicitly registered rather than filled with invented facts.

## Base and controls

- [ ] Eleven core and six orchestration tables mapped from both schema contracts.
- [ ] Required fields/types/options, computed fields, links and cardinality mappings read back.
- [ ] Audit affected-row identity distinguished from the event's own record ID.
- [ ] Business keys checked within scope; native record IDs preserved.
- [ ] Context Registry and five Stage Config rows populated and linked.
- [ ] Pause applications is true, submission cap zero and scope empty for a fresh install.
- [ ] Existing user controls preserved; unknown policies do not mean unlimited.
- [ ] Audit capability/retention/enforcement gaps recorded honestly.
- [ ] Inventory storage profile explicitly recorded; existing/default behavior not silently changed.

## Harness and recovery

- [ ] Repo/fork and base bootstrap saved in every intended harness.
- [ ] Current harness can perform required audited reads and writes with readback.
- [ ] Marked private setup fixture create/read/update/archive preserves field history.
- [ ] Authorized small Drive fixture write/readback and reference works.
- [ ] Fresh session recovers references and saved fixture without prior chat/local files.
- [ ] Stage-specific web, document/PDF, browser or mailbox capability tested or marked missing.
- [ ] Interrupted-write, stale-input and uncertain-submission behavior checked with safe fixtures/simulation.
- [ ] One active owner, explicit plan/manual sequence and stop/partial behavior understood.
- [ ] No real job search, fit decision, resume readiness or submission falsely claimed by setup.

## Private handoff

- [ ] Actual workspace/base/folder/content references and schema map recorded privately.
- [ ] Per-stage readiness lists tested harness, evidence, blockers and next action.
- [ ] Bootstrap instructions and ownership/recovery procedure supplied.
- [ ] User can choose one harness or several without changing stage acceptance rules.
