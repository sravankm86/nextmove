# Track

Use COMMANDS.md. Recruiting mail is read-only: do not send, draft, label, archive or delete. Missing account/scope access is a capability blocker, not completed reconciliation.

Read the successful mailbox checkpoint from Settings/Run, overlap the prior window, paginate all relevant results and deduplicate stable message/event identities. Match exact requisition/job identity or unambiguous evidence; company-only acknowledgements remain unresolved.

Receipt → Confirmed; actual recruiter engagement → In process; explicit offer/acceptance/rejection/withdrawal/cancellation → corresponding outcome. Preserve actual event time separately from recording time. Older acknowledgement cannot regress stronger/later history. Contradictions require correction evidence, not an assumed reversal.

Record exact message/receipt identities, confirmation/outcome dates and evidence in History, and current lifecycle/Confirmation reference on Applications. Follow STAGE-STATE.md; removing a redundant column never removes actual event times. An event can matter even without a state change. Preserve source IDs so polling is safe to repeat without duplicates. Runs/Settings retain mailbox cursor, scope, counts, unresolved IDs and successful coverage; no separate Mail Audit table.

A rejection changes a company hold only under a confirmed applicable rule. Uncertain submissions are reconciled, never resubmitted automatically. Verify all changes and handoff before completion.

For a first Track run without a successful checkpoint, use the earliest known application/observation date among the tracked scope as the start, record that basis, and paginate all relevant results. If that boundary cannot be established, ask for the initial time range under CLARIFICATIONS.md. A bounded access probe is not reconciliation and must not advance the mailbox checkpoint.
