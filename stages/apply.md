# Apply

Default is preflight. A full Run, a Ready resume or a bare Apply command does not authorize unlimited submissions.

Read live pause/stop, explicit scoped authorization, answers, exact role history, current role availability, review/master/resume versions and every applicable company quota/cooldown. Reconcile uncertainty. Generic rejection does not establish company-wide restriction; unknown rule/scope/boundary or answers block affected submissions. See docs/COMPANY-RESTRICTIONS.md.

Only supported authorized browser actions may submit. Follow RESUME-FILES.md to verify the exact PDF file/version. Before Submit, persist/read back Submission attempt key and Submission run on Applications and a durable History intent/checkpoint with exact role, PDF file identity/version and approved answers under STAGE-STATE.md. Reconcile an existing attempt before retry even if the UI status says Ready. Capture actual success/receipt, date and evidence. Definite submission → Applied; exact-role receipt → Confirmed; unresolved possible submission → Submission uncertain. Never retry blind or infer non-submission from absent mail.

Keep meaningful attempt/receipt events in History and current state on Applications. Runs records stage progress and blockers. No general Task Attempts table is needed.

Use one submission writer and respect human edits. Do not send recruiting mail. Single-stage invocation stops at its handoff; a full Run can continue Track or other unaffected authorized work while reporting blocked submissions.

Before advancing, verify that the accepted review still matches the current goals, role policy, master and job description. Changed inputs require affected review/re-preparation, not silent reuse. Preserve existing submitted/terminal history.
