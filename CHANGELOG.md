# Changelog

## Career Goals used at both boundaries

- Derive and verify broad Scan role criteria from the current user preference source; Review uses the broader projection for Queued approval.
- Add source-versioned extraction and per-stage/decision completeness checks with targeted clarification, optional unknowns and manual-handoff recovery.


## Preference-only career goals

- Keep user goals free of agent instructions, resume history and execution configuration.
- Add an optional preference-only template and Git-owned interpretation contract supporting prose, hard/soft preferences, unknowns and source-versioned extraction.


## Candidate inventory and Review-owned queuing

- Scan inventories plausible PM candidates after keywords/basic semantics; no career-goal checks or Queued approvals.
- Review owns final eligibility and career/resume checks; Queued replaces new Shortlisted emissions as the preparation queue. Preserve legacy states with evidence-based migration.
- Add structured disposition feedback and versioned, recall-tested scanner improvements. Career mismatches are not automatically scanner mistakes.
- Version 3 public schema/commands/configuration; live migrations remain explicit and independently verified.

## Previous revision — six-table design (scan boundary superseded above)

- Prefer one thorough single-agent Run; manually switched stages use identical gates and checkpoints.
- Consolidate operational state into Companies, Applications, Sources, Runs, Settings and History. Retire generic orchestration tables.
- Verify PM function and configured experience/equivalent senior scope before inventory. Screen career goals before Queued, with recall-oriented pending checks instead of premature rejection.
- Replace routine per-read journal rows with meaningful change/business-event history and Run read scope.
- Make description capture admission-focused; clear unrelated roles are processed transiently, not stored in a shadow inventory.
- Preserve legacy outcomes and provenance during authorized verified migration; unreviewed broad queues require revalidation.

Earlier revisions introduced the larger workflow schema and full raw catalog storage. Those are migration aliases/evidence, not the active fresh-install design. MIT licensing, public onboarding, contributor/security guidance and dependency-free repository checks remain.

No installed runtime, account provisioning, production scan or certified harness integration is implied by these docs.
